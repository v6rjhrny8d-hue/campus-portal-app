## 1.5.1

## 1.5.0 简化设置与统一卡片

删除高级配置和登录网址入口，移除保存设置／保存并测试按钮。表单停止输入约 0.9 秒后自动保存，离开设置或应用时也尝试保存；账号密码未填完整时保留原账号。任务运行期间暂缓保存，任务结束且界面可用时继续。首页仍可立即登录或仅检测。

连接记录默认收起，可全部展开、全部收起或单条展开，不再按主要／详细事件过滤。三个主页顶部的标题、英文说明和记录介绍已删除。页面延伸到系统手势横条区域，导航仍避开手势触摸区。

移除 Dock 后方固定留白形成的整条底色，让页面内容延续到胶囊后方。滚动视口内部保留底部余量，最后一项仍可滚动到按钮上方；设置保存按钮使用无背景悬浮行，键盘弹出时导航隐藏。胶囊本身继续使用实色，轮廓边线减淡，阴影采用贴合胶囊的低透明度系统阴影。

本版通过 69 项 Android 模拟测试和明暗布局渲染检查；实际手机阴影观感尚未实测。

## 1.4.1 实色界面与时间滚轮

全部卡片、弹窗和底部导航改为不透明实色，移除背景模糊及导航截图绘制。默认使用雾霾蓝，保留六套主题与明暗切换；已经主动选择的其他颜色不强制覆盖。使用指南只有一个裁切后的内容滚动区域，隐藏滚动条和边缘效果。设置页保存按钮与导航分别占据布局区域，没有覆盖输入内容的底部背景层。

时间设置改为闹钟式双列数字滚轮：单条选中底色、冒号、惯性滑动、逐格吸附、开始／结束切换。支持跨午夜、时段校验、取消不生效、辅助操作和键盘方向键。点击“确定时间”只更新表单，仍需“保存设置”。重复点击确认或应用主题只执行一次。小屏和大字体时可以滚动到确认按钮。

账号、定时、Wi-Fi 绑定及已验证的认证流程保留；本版没有更改后台执行核心。覆盖安装后打开一次，核对下次计划。详细检查与实机限制见 `docs/RELEASE-1.4.1.md`。

## 1.3.6 使用体验

设置中的开始、结束时间使用 24 小时时分滚轮，支持跨午夜、取消和时段校验；滚轮触感可在设置中关闭。点击“确定时间”只填入设置，仍需点击“保存设置”。首页和设置均可打开离线使用指南；“夜间运行检查”提供系统授权状态、手动检查入口和熄屏自测。自测结果默认显示简要结果，可查看完整细节；记录页默认显示主要事件，可展开详细记录。

全新配置默认 07:00—07:05；已保存的时段不修改。首页未运行任务时的界面刷新间隔从 3 秒调整为 15 秒，进入后台原本就停止界面刷新。认证、系统闹钟、唤醒锁和重试策略沿用 1.3.5；没有在此版本声称已测出省电百分比。

本版以可用的 1.3.5 源码为基础，不包含可能只存在于其他电脑上的后续源码。已通过 247 项核心断言、52 项 Android 15 模拟测试及原签名验证；Android 16 手机安装和隔夜运行仍需实际验证。

## 1.3.1 后台任务与超时恢复

直接覆盖安装 `campus-portal-app-1.3.1.apk`，不要先卸载。原签名、账号加密密钥、网络绑定、登录网址、时段和开关保留。更新后打开一次应用，核对下次计划。

- 前台服务只在任务开始时进入前台，后续进度只更新通知。系统超时、用户停止、计划关闭、时段结束分别记录；停止时取消连接、工作线程和唤醒锁，旧任务不能覆盖新结果。
- 增加独立于网络线程的截止检查，同时使用北京时间和单调时钟；校时或网络卡住不会让任务无限延长。
- 系统拒绝启动或超时结束定时前台任务时，在本时段内尝试 Android 系统备用任务。优先申请加急，无额度时申请普通调度。每次至多 90 秒，失败后按原间隔请求下一次；仍只通过绑定的 Wi-Fi 认证，已成功、用户停止、配置变化或时段到期就跳过。
- 备用任务不是准时执行保证：休眠、后台限制、Wi-Fi 和系统任务额度仍可延迟它。到期后不会补交账号，也不会反复重启已受限的前台服务。
- “停止本次任务”同时取消已排队的备用检测，并阻止本时段自动补跑；保留下次自动计划，仍可手动登录。重新关闭再开启自动计划可明确重新启用本时段。
- 日志扩展至最近 1000 条，页面显示最近 200 条、导出包含全部；包含任务编号、实际运行时长、超时类型、请求耗时及任务当时的休眠/省电/VPN/Wi-Fi/DNS 状态。日志仍不含账号密码和完整登录查询串。

10 月 23 日日志已经确认前台服务刚启动就收到系统超时回调，但现有证据不足以确定系统计时异常或厂商限制的最终原因。本版修复任务生命周期风险并提供备用执行路径，不声称已在用户手机上完成隔夜验证。学校认证服务器不可达时，本版也无法替代学校网络恢复。

本版通过 230 项 JVM 核心断言和 15 项 Android 15 生命周期模拟测试，另完成 SDK 35 构建及同签名验证。测试细节与实机验收步骤见 `docs/RELEASE-1.3.1.md`、`docs/VALIDATION-1.3.1.md` 和 `docs/testing.md`。

## 1.3.0 指定网址和内置登录网页

1. 覆盖安装 `campus-portal-app-1.3.2.apk`，保留现有账号和绑定配置。
2. 设置 → 登录网址，粘贴浏览器地址栏中的**完整原始登录链接**并保存。没有完整链接时，可点“使用认证服务器入口”测试入口能否取得当前参数；不会补猜缺失参数。
3. 首页 → “访问链接并自动登录”：先通过已绑定 Wi-Fi 访问此链接，再使用已保存的账号、密码和服务认证；最后验证 HTTPS 联网。此入口不依赖公共探测地址先成功。
4. “打开登录网页”可显示学校页面。网页内点击“自动登录”时，会把当前受信任页面的链接传回原生认证流程，用于本次登录；支持网页 JavaScript 导航后取得的新参数。也可以在网页手动操作，点击“我已在网页登录，验证 Wi-Fi 联网”确认结果。
5. 1.3.2 中所有原生检测/登录先验证 HTTPS。未联网时，普通“立即登录”和定时任务会先尝试保存的网址；取不到认证页再回退原来的自动探测。留空则保留旧版流程。已有时段、间隔和开关不自动改变。

登录网址仅接受当前配置认证服务器的 HTTP 80/8080 地址。自动提交仍只接受该服务器的 `/eportal/index.jsp?…`，密码不注入网页脚本。内置网页使用独立进程绑定选定 Wi-Fi，退出页面释放绑定；切到后台会关闭网页。页面仅加载配置的服务器资源，其他网站或外部应用跳转会阻止。

保存的链接可能过期。页面打开、认证接口返回成功、Wi-Fi 的 HTTPS 验证通过是不同结果。账号拒绝后仍冷却 15 分钟，不会持续提交。导出的配置清空登录链接，诊断日志不包含完整查询串或账号密码。

1.3.0 当时通过 192 项离线核心断言、SDK 35 编译及同签名校验。开发环境对学校认证入口连接失败，未提交真实账号；手机 WebView、实际认证、锁屏定时和覆盖安装保留数据仍需宿舍网络下实测。

独立安卓应用，支持宿舍网络绑定、校园网认证、定时检测、权限引导和连接记录。无需 Termux、额外助手或 Root。包名 `org.campusportal.app`，支持 Android 8.0 及以上。

## 1.2.1 认证页探测修复

补齐认证服务器内的中间跳转、简单 JavaScript 导航和 meta refresh；增加普通 HTTP 探测与已配置服务器入口回退。收到带 Location 的重定向时先保留跳转头，避免正文超时丢失地址。记录增加主机、HTTP 状态和异常类型，排查时可导出，不记录认证查询串和账号密码。

未设置指定网址时，每次获取当前网络返回的认证参数。1.3.0 起可主动保存完整链接作为优先入口；实际学校网络是否恢复自动认证，需要在尚未手动登录时验证。

## 覆盖更新

直接安装 `campus-portal-app-1.5.0.apk`，选择更新。不要先卸载旧版，也不要清除应用数据。沿用同一签名、存储格式与 Keystore 别名，账号、绑定网络、服务、时段、星期、间隔与自动计划开关应保留。

更新后打开 APP，核对设置和下次计划。已有检测时间不会自动更改；“快速填写 07:00—07:05”只是填写按钮，需要保存才生效。系统后台设置与真实定时效果仍需手机检查。

## 首次使用

首页显示“三步准备”：

1. 先在系统连接自己的宿舍 Wi-Fi，再到设置点击“绑定当前 Wi-Fi”。应用保存网关和网段，不依赖定位权限；网络备注只是方便识别的名称。
2. 填写自己的校园网账号、密码，并选择与认证页相同的服务类型。点击“保存设置”。首次保存或更换账号时需要同时填写密码；已有账号的密码框留空表示保留。
3. 点击“保存并测试”，或回首页点击“立即登录”。只有通过选定 Wi-Fi 的实际 HTTPS 网页验证，才记录联网验证成功。

没有绑定网络时，“保存并测试”会提示先绑定，并保留填写内容。错误在页面顶部持续显示，处理后可以收起。账号或密码缺失时也会在字段旁提示。

## 开启自动计划

先测试一次连接，再设置时段、重复星期和检测间隔。全新配置默认北京时间每天 **07:00—07:05、每 60 秒检查**；更新不会覆盖已经保存的时间。支持跨午夜，单次时段最长 2 小时，间隔 30—300 秒。

在“运行准备”查看准时启动、通知、电池优化及厂商自启动。按功能提示完成设置，再开启首页的自动计划。首页应显示下一次实际计划时间；没有准时启动授权时会显示待授权，不能把开关开启当作已成功安排。

### 到点后的行为

- 系统唤醒后，通过已绑定的宿舍 Wi-Fi 检测与认证。
- 已联网，或认证后通过 HTTPS 验证：立即结束本次任务，释放唤醒锁，移除运行通知，保留下一次计划。
- 未通过验证：按间隔重试，最迟到时段结束停止。
- 同一时段成功完成后，重新打开应用不会自动补跑。仍可手动登录。
- 成功停止后若再次掉线，需要手动登录或等待下次计划。

关闭自动计划会取消计划并停止当前任务；“停止本次任务”停止当前操作、取消备用任务并暂停本时段补跑，保留计划开关。

## 如何读首页

| 内容 | 表示什么 |
|---|---|
| 上次联网验证成功 | 最近一次检测成功，不代表当前持续在线 |
| 最近检测时间 | 该结果发生的时间 |
| 当前任务：待机 | 当前没有检测任务运行，可以与自动计划开启同时存在 |
| 任务进行中 | 正在检测、认证或验证，可停止当次任务 |
| 自动计划 | 是否开启、缺少哪些准备以及下一次时间 |

本应用不在设定时段外持续监测，不显示全天实时网络状态。认证接口返回成功而网页未验证时，仍显示尚未验证。

## 移动数据与 VPN

移动数据可以保持开启，检测与认证走选定的 Wi-Fi，不使用移动数据的结果冒充 Wi-Fi 联网成功。

使用 VPN 时，在客户端的应用访问控制中排除“校园网助手”，包名 **org.campusportal.app**。修改后重新连接 VPN。系统的强制 VPN 或“阻止未使用 VPN 的连接”仍可能禁止直连，本应用不能覆盖这些策略。它也不会自动开关 Wi-Fi、移动数据或 VPN，宿舍 Wi-Fi 需要系统自动连接。

## 记录、诊断和高级设置

“仅检测”和“验证网页访问”不提交账号。连接记录保存最近 1000 条事件，可导出，不记录账号密码、完整认证查询串或服务器原始错误回复。

高级设置保留认证服务器、网关、网段和 JSON 参数，只解析配置，不执行代码。默认认证服务器为 `10.100.1.5`，支持本校当前适配的 RG-ePortal 协议。其他协议、验证码或额外密码加密需要另行适配。

## 分享给同校其他宿舍

可以分享 APK；对方连接自己的宿舍 Wi-Fi、重新绑定并填写自己的账号后测试。

导出配置不含账号密码。导入后自动计划关闭，需要重新检查本宿舍的绑定、账号和认证服务，测试后再开启。不要把含真实账号密码的旧 Termux 配置分享出去。

## 从旧 Termux 方案迁移

可直接在新应用填写账号，也可通过设置导入旧 `config.json`。导入文件含凭据时会先说明并确认，再在本机加密保存。

确需从 Termux 导出时：

```sh
cp "$HOME/campus-portal/config.json" "$HOME/storage/downloads/campus-old-config.json"
```

该文件可能含明文账号密码，导入后删除下载目录副本。新应用测试通过后再停止旧任务和开机脚本：

```sh
cd "$HOME/campus-portal"
python portal_android.py stop
python portal_android.py uninstall-boot
```

旧“校园网 Wi-Fi 助手”不再是本 APP 的依赖。

## 常见问题

| 提示／现象 | 处理 |
|---|---|
| 尚未设置 | 按首页三步准备完成绑定、账号和测试 |
| 认证未通过 | 点“检查账号与服务”，核对密码和认证页服务类型；拒绝后有 15 分钟冷却，修正并保存可重新测试 |

| 加密凭据不可读取 | 重新填写账号密码；卸载或清除数据会移除本机凭据 |

## 账号数据与测试边界

凭据使用 Android Keystore 的 AES-GCM 密钥加密保存在应用私有存储，禁止系统应用数据备份。没有自建服务器、广告或统计 SDK。学校认证协议当前使用 HTTP，本机加密不会使认证传输自动变成 HTTPS。

验证记录见 `docs/VALIDATION.md`；设计与版本变化见 `docs/RELEASE-1.2.1.md`；构建、源码结构和扩展入口见 `docs/DEVELOPMENT.md`。
