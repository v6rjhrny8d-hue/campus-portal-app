# 1.2.1：认证页发现与跳转兼容性修复

日期：2026-10-17（北京时间）。

## 现场证据与结论边界

用户记录显示，07:03、07:04 已选择绑定的 Wi-Fi，但未取得受信任的认证页，07:05 按时段停止。用户确认浏览器手动登录正常，提供的地址主机为 10.100.1.5、路径为 /eportal/index.jsp，包含 wireless-v2 及本次网络参数，符合原有协议的地址校验。

这排除了“所提供网址的主机或页面路径不受支持”这一解释。原记录未保留每个探测的状态与跳转链，因此尚不能证明哪一条请求是这次手机失败的直接原因。此次修复针对检查中发现的明确实现缺口，最终自动认证结果需要手机验证。

## 修改

1. 原先只解析每个探测地址的一次响应。现在可继续读取同一已配置认证服务器上的 HTTP 跳转、简单 location 导航和 meta refresh；最多读取三步，记录已访问地址，防止循环。不执行网页脚本。
2. 原先先读取响应正文再返回 Location。现在带 Location 的 3xx 响应直接保留跳转头，不等待无须使用的正文，避免正文迟迟不结束或超时而丢失地址。正常正文仍限制 64 KiB，并检查取消及截止时间。
3. 在原有三个探测地址之外增加普通 HTTP 网页探测。原探测未发现认证页且 HTTPS 验证失败后，尝试当前配置的认证服务器根入口和无查询串的认证入口。每次从新响应提取参数，不内置、保存或重放用户本次提供的链接。
4. 最终认证页的 GET 可接续受信任地址上的参数刷新。认证 POST 仍只向已配置主机的现有接口提交，不自动跟随 POST 重定向。
5. 探测记录增加请求主机、HTTP 状态、异常类型、是否继续跳转及是否发现当前页。不记录正文、完整网址、认证查询串或账号密码。

## 升级与保留

沿用 org.campusportal.app、同一签名、原有设置格式和 Keystore 别名。账号存储代码与界面代码仅改版本文字；Config、MainActivity、ScheduleManager、ScheduleReceiver、Schedule 与 1.2.0 逐字节一致。WorkService 仅增加诊断日志回调，保留原任务循环、截止时间、成功提前结束、唤醒锁释放和下次安排逻辑。

直接覆盖安装，选择更新，不先卸载或清除数据。已连通网络上的一次成功只证明网页可访问；认证修复需要在尚未通过学校认证时测试“立即登录”。若仍失败，导出本版日志用于定位具体请求。

验证详见 VALIDATION.md。1.2.0 的界面更新记录仍保存在 RELEASE-1.2.0.md。
