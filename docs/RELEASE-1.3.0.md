# 1.3.0 · 指定登录网址

## 实现

- 新增 `Config.loginUrl`，完整原始参数仅保存在应用私有配置中。旧配置缺少此字段时为空，保持自动发现。共享导出清除此字段。
- 首页新增“访问链接并自动登录”“打开登录网页”；设置可保存完整网址或填入已配置服务器入口。
- 指定链接模式先 GET 用户网址，提取当前服务器返回的参数后认证。无需先成功访问公共探测地址；未取得认证页时明确不提交账号。
- 普通登录和定时模式优先保存的网址，再回退已有探测；已能通过 HTTPS 上网时不重复认证。
- 修正直接页面发现：保留其原始查询串；优先 HTTP / JavaScript / meta 更新后的参数；HTTP 错误页不视作可用认证页。
- `PortalBrowserActivity` 是未导出的独立进程 Activity，创建 WebView 前绑定已选择 Wi-Fi，退出/断网清理。Activity 不读取账号、不写 SharedPreferences，不向网页暴露原生接口。
- 浏览器只允许配置认证主机的 HTTP 80/8080 页面和资源，禁用文件/内容访问和跨域第三方资源，不忽略 TLS 错误。系统 WebView 需可用。
- 网页“自动登录”只把验证过的当前认证页 URL 作为一次任务参数返回主进程；原生认证重新获取页面，保留密码加密要求、拒绝冷却、取消、截止时间及 HTTPS 验证。
- 保留包名、Keystore 凭据别名、设置 schema 和原签名；版本码 10300。

## 验证

- 核心 192 项断言通过，其中增加 31 项：直接访问顺序、原始编码保留、查询更新、仅检测、已联网、冷却、错误页、回退、加密限制、取消、网址验证及旧配置兼容。
- SDK 35 / Build Tools 35.0.0 编译、APK 签名验证通过；与 1.2.1 签名证书 SHA-256 相同。
- 开发环境无可用 Android 模拟器/用户设备，未执行 instrumentation 或真实覆盖安装测试。
- 对 `http://10.100.1.5/eportal/index.jsp` 的直接连接失败（curl HTTP 000 / exit 7），无法从开发环境验证学校内网或实际账号认证。此次没有向服务器提交真实账号。
- 先前长链接记录末尾被截断；未重建缺失参数，需在手机粘贴完整原始网址。

## 手机验收

1. 直接覆盖安装后检查账号、网络、计划仍在；保持移动数据开启，连接宿舍 Wi-Fi。
2. 粘贴学校完整登录链接、保存；点首页指定链接登录，查看记录是否先访问指定服务器。
3. 未认证时测试自动提交、认证成功后 HTTPS 验证；已联网时应不再提交账号。
4. 打开网页，确认页面、样式和脚本可用；如跳转更新参数，可点网页工具栏的自动登录；也可手动登录后验证。
5. 旧链接失效/服务器不通时，应说明未取得认证页且未提交账号。按停止应结束任务。
6. 自动计划继续使用原时段，成功提前结束；锁屏隔夜是否稳定须真实环境确认。
